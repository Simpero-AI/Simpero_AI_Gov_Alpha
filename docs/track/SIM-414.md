## Implementation Notes

### Summary
`load_workspace_config` previously read `investment_profiles.mandate`, a
table nothing in the app has ever written. Repointed it at `mandates` (the
table `PUT /api/mandate` actually writes) and added a transformer for its
stored blob shape. No migration; single source of truth is the row the user
edits.

### Design decisions
- **Category matching precedence:** `category_id` → `slug` → display-name
  fallback, mirroring `_mandate_item_key` in `app/api/mandates.py`. Needed
  because the canonical sector category is named "Target Sectors" (slug
  `target_sectors`), not "Sectors" — display-name-only matching would have
  missed it. `workspace_config.py` copies the two slug strings rather than
  importing the admin schema's enum (admin/product code don't share modules
  per CLAUDE.md); a test pins the copy against the real enum so it can't
  drift silently.
- **Sub-option containment:** a parent selected with no `sub_options`
  approves itself and its **entire taxonomy subtree** (not just one level) —
  "Canada" alone approves a deal HQ'd in Ontario. A parent selected with
  `sub_options` approves only itself plus those listed children. Full-subtree
  rather than one-level because the Builder's depth-1 UI cutoff is a UI
  limit, not a policy one. Recursion carries a cycle guard (`parent_option_id`
  is a self-FK that permits one).
- **Matching:** fold-only (NFKC → collapse whitespace → casefold) on both
  sides, no alias/synonym table. `"US"` does not match `"United States"` —
  deliberate; the durable fix is a shared vocabulary between the deal form
  and the taxonomy (SIM-402 territory), not a hardcoded alias map.
- **Three-state semantics, now per-category:** `None` (⇒ `unknown`) is the
  result whenever a category has no *usable* selection — whether because the
  org has no mandate row, the category is absent, `options` is `[]`, or every
  option in it failed to parse. Only a category with at least one usable
  option produces a real (possibly empty… no, non-empty by construction)
  list. This was a deliberate design choice: resolving "category present but
  empty" to a real `N` would auto-fail every deal against a policy the firm
  never actually set.
- **Defensive parsing:** the blob is unvalidated `list[Any]`
  (`UpsertMandateRequest.mandate`) and this code runs inside the screening
  background job, whose failure path fails the whole `analysis_run` — so
  every malformed shape is skipped with a `logger.warning`, nothing raises.
- **Not cached:** gs_07/gs_08 each call `load_workspace_config`
  independently (as before); cost is 1 SELECT when no mandate exists (common
  case, unchanged from before), 3 when one does. Explicitly rejected a
  process-level or session-keyed cache — per-org data on an RLS-scoped
  session makes a process cache a cross-tenant leak risk, and a session-keyed
  one would rely on "one session = one org", which is a convention in this
  codebase (`admin_dependencies._set_org_scope` breaks it deliberately for
  cross-org admin writes), not an invariant.

### Bug found and fixed along the way
`MandateRepo.upsert`'s `on_conflict_do_update(...).returning(Mandate)` was
handing back the stale identity-mapped ORM instance instead of the actual
`RETURNING` row. Since `PUT /api/mandate` always loads the previous row first
(for the audit diff), every **update** silently echoed the **old** mandate
back to the caller — the row on disk was always correct, but the frontend
would have re-rendered pre-save selections after every save. Fixed with
`execution_options={"populate_existing": True}`. Caught by the new
`test_put_mandate_replaces_rather_than_merging` — `PUT /api/mandate` had no
test coverage before this task.
